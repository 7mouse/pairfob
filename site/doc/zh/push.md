# 通知

电脑端默认开启发送能力。手机授权并订阅后，Agent **等你处理**或从工作中变成**完成**时，会推到已订阅的设备。点通知回到**那台电脑的那个会话**，而不是只打开首页。

完成通知只认 `working → done`。pairfob 刚启动时即使读到已经完成或正在等你的会话，也不会补发旧通知。

当前不区分通知类型：「等你处理」和「已完成」会一起订阅，不能分别设置。同一会话的状态更新会替换旧通知，完成后不会在通知栏里留下过时的「等你处理」。

没有通知也能用 Pairfob：打开网页或主屏幕图标，列表里「等你」的卡片仍然醒目。

## 电脑端设置

默认开启发送能力。Pairfob 在本地生成并保存推送签名密钥，默认联系地址为 `https://pairfob.com`。升级会修复旧的 `mailto:operator@localhost` 占位地址，保留密钥、订阅和自定义联系地址。

曾经手动关闭后，可运行以下命令重新开启：

```sh
PAIRFOB_PUSH=1 pairfob service install
```

命令会保存设置并启动后台服务。重装会保留服务定义中已有的推送设置；命令中明确传入的非空值优先。普通的 `pairfob service restart` 不会从当前 shell 导入环境变量。

如需自定义联系地址，请使用自己控制的有效 `mailto:` 或 `https:` 地址：

```sh
PAIRFOB_VAPID_SUBJECT=https://example.com/contact pairfob service install
```

不要使用 localhost 地址。修改联系地址不会更换签名密钥。上述设置直接保存在服务定义中；安装程序不会导入外部 systemd 环境文件。

## 手机上订阅

配对后，在通知引导卡片中点**开启**；也可以稍后到 **设置 → 通知** 开启。点“稍后”会关闭这台电脑的引导，重连不会再次弹出。

iPhone 和 iPad 需要先将 Pairfob **添加到主屏幕**，从主屏幕图标打开，再点开启并接受系统授权。只有点击后才会请求权限。如果之前拒绝过，请先在系统通知设置中修改权限。

不支持 Web Push 的浏览器不会假装开启成功。旧版电脑端请先升级。如果电脑端被明确关闭，设置页会给出重新开启的命令。

一个浏览器已有的订阅绑定一台电脑的签名密钥。Pairfob 不会悄悄替换另一台电脑的订阅；如需另一台电脑的通知，请使用另一个浏览器配置文件。多电脑配对和远程操作不受影响。

服务和推送服务商处理哪些数据，见[隐私说明](/zh/privacy)。

## 点开通知之后

应进入对应的会话。若那个会话已经不在了，会回到列表并提示「这条通知对应的会话已经不在了」。

## 关通知

- 手机：在系统设置里关掉该站点的通知，或解除这台设备的配对
- 电脑：运行 `PAIRFOB_PUSH=0 pairfob service install`。已有订阅不会再发出「等你」或「已完成」推送

丢失设备先 [解除配对](/zh/devices)，不要只关通知。
