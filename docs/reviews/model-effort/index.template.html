03 / DETAILS

轻点，展开依据。

手指操作打开底部面板；鼠标点击打开信息卡。保留执行步骤入口，同时显示这一轮的完整模型 ID、effort 和数据依据。

01 / DECISIONS

把确定的事，说清楚。

MODEL

展示实际观测到的模型

执行摘要可用短名称，详情保留完整 ID。只识别显式白名单别名；未知名称按原值显示。长名称截断，详情完整换行。

THINKING EFFORT

保留原始档位

显示「思考 high」等原始值，详情解释含义。不同 Agent 的档位不强行折算；没有字段显示「未提供」，不从思考文本或耗时推断。

EVIDENCE

每个值都带依据

记录必须属于同一会话、同一轮。只知道会话最新值或下一轮设置时，不能写到历史执行卡片上。离线仍能显示已绑定的历史事实。

A. 数据采集：先 Codex，再逐个适配

在 internal/journal 增加独立的模型观测解析模块，不把设置记录塞进聊天文本。Codex 优先核对真实日志中的 turn_context 模型与 effort 字段；只有经过样本验证才启用。Claude 先读回复的实际 model，effort 缺失保持未知。

Claude 的 effort 可作为后续状态上报接入：先验证已安装版本的 statusline / hook 数据，再按当前 session 绑定。Pi 等 Agent 单独适配 model / thinking 变更事件。各适配器未知字段忽略、格式变化失败关闭。

B. 数据边界：按轮次保存，不是会话最后值

内部观测按 daemon / session / agent instance / 稳定轮次标识保存，字段包含 model、effort、source 与 recordedAt。旧轮次在新回复到达后保持原值；当前轮缺 effort 不继承上一轮。

同轮若确实有多个模型，摘要显示“多个模型”，详情按记录展示，不能挑最后一个代表整轮。仅有设置上报或会话级最新值时，本轮显示“模型未记录”。

C. 传输：需要先解决轮次关联

上一版的 Pane.tokens 方案只能表达会话级观测，无法可靠标记历史回复。这版不能直接沿用。先验证 journal 的轮次关联是否能跨分页、增量刷新、日志轮换保持稳定；不能用数组下标或文字相似度拼接。

实际接入前需要另行设计带轮次标识的只读扩展契约和能力协商，遵守现有冻结协议，不修改现有 RPC 字段。旧 daemon 没有这项能力时，仍展示原来的步骤和用时。当前 HTML 只演示目标界面，没有实现该传输能力。

D. PWA：补充执行卡片的现有摘要

在 features/session/chat/work-card.tsx 的用时旁渲染模型与 effort，用同一轮的视图数据驱动。保留执行卡片原来的步骤详情行为，模型依据作为详情中的补充内容。标题恢复状态、Agent 类型和工作区；输入区保持原高。

窄屏优先保留用时与 effort，长模型名省略；详情保留完整 ID。整张卡片保留触控命中范围，宽度只影响布局，触摸和鼠标分别打开底部面板与信息卡。关闭后焦点回到同一张执行卡片。

首版交付范围：按轮次显示模型、原始 effort、依据和记录时间；支持缺失、断连、长名称和实例切换。
独立后续项：模型 / effort 修改器。修改器需要 Agent 专用控制能力和结果回读，不能写 metadata 冒充切换。
04 / ACCEPTANCE

如何确认它值得信任。

数据验收

  • 真实 Codex / Claude 样本核验字段、轮次、会话身份；加入缺字段、轮换日志、重复记录和损坏行样本。
  • 同 pane 重启、跨电脑同名会话、快速切换 Agent 不串值；分页与重连后旧轮次不串值，新轮次缺字段不沿用旧值。
  • 修改 journal 时执行真实日志扫描：PAIRFOB_SCAN_LOCAL_TRANSCRIPTS=1 go test ./internal/journal -run LocalTranscripts -v。

界面与交付验收

  • 在 pwa/qa 增加七种状态；390×844、820×768、1024×768 真实触摸检查，1440×900 鼠标与键盘检查。
  • 窄屏鼠标仍是信息卡；宽屏触摸仍是底部面板。读屏可读完整值；详情不触发软键盘。
  • 检查标题与输入框尺寸、消息阅读位置与终端 resize 不受影响。后端与跨模块实现完成后跑完整 verify，再单独验收真实传输与物理设备。
