# Pairfob 自动安装 Herdr 与首次使用实施方案

状态：实现已完成，Docker 完整仓库验证、真实链路和 macOS launchd + Herdr 生命周期验收通过；后续大文件超时排查及最终 Docker 全仓回归也已完成，证据见末尾。真实注销登录和物理设备仍待验收。适用范围：macOS 与 Linux 上的 Pairfob 安装、首次会话、电脑端使用和本机 Herdr 更新。更新日期：2026-10-14。

用户只需安装 Pairfob。缺少 Herdr 时，安装器自动下载官方最新稳定版，完成校验、后台启动和接口检查。用户随后配对想使用的设备，进入已有会话或创建第一个会话。已有 Herdr 用户继续使用原来的服务和工作区。

Pairfob 负责自己安装的运行组件的诊断和本机更新入口。更新默认保留运行中的任务；需要停止服务才能生效时，明确列出影响并由用户选择时机。安装来源、已安装版本、运行版本必须分别记录和展示。

本文前十一节保留设计与验收要求，末尾“实施与验收记录”列出本次已实现、已验证和仍待实机验收的范围。本地实现不代表生产版本已经发布。

## 一 产品目标与范围

目标用户首先是已经使用或准备使用 Codex、Claude 等 Agent CLI，但没有使用过 Herdr 的开发者。Pairfob 自动准备会话运行环境；Agent 账号、订阅和登录仍由对应 Agent 管理。

用户需要理解的操作只有：安装电脑端、配对浏览器、打开或创建会话、在其他设备继续。Herdr 在安装进度、电脑终端入口、诊断和更新时以“会话运行组件 Herdr”出现。

| 第一版必须完成 | 后续独立评估 |
| --- | --- |
| 默认自动安装最新稳定版 Herdr | 定时下载与无人值守自动升级 |
| 复用已有 Herdr，检查真实接口 | 自动判断空闲并重启服务 |
| 安装来源记录和本机更新入口 | 手机远程统一升级多个组件 |
| 空会话创建、路径说明和失败恢复 | 无会话时的远程目录选择器 |
| 电脑浏览器及本地终端入口 | 独立桌面客户端 |
| PATH 和重新登录后的可用性验证 | 统一安装、登录和管理所有 Agent |
| 明确退出、重启、卸载的结果 | 自动清理全部依赖和用户数据 |

保持现有加密、配对、内层 RPC 字段、操作账本和路径权限约束。本次不增加远程安装或更新 Herdr 的 RPC，不修改 relay，不创建另一套 Herdr 身份或专用工作区系统。

Herdr 官方提供 Windows 版本，不等于 Pairfob 本次增加 Windows 主机支持。浏览器作为控制端的支持范围与运行 Pairfob 的主机支持范围分别说明。

## 三 用户从安装到日常使用

### 新用户已有 Agent CLI

1. 在运行 Agent 的 macOS 或 Linux 电脑执行安装命令。
2. 安装器下载 Pairfob；缺少 Herdr 时自动下载最新稳定版，启动默认服务，验证就绪。
3. 运行 `pairfob pair`，在想使用的设备打开 `https://pairfob.com/pair`，扫码或输入配对码，再在电脑上确认。
4. 有会话则进入原会话；没有会话则点“创建第一个会话”。
5. 输入目标电脑上的项目绝对路径，选择 Agent 类型并创建。
6. 启动成功后进入会话。登录提示在对应 Agent 的终端中完成；需要本机浏览器授权时明确回到运行 Agent 的电脑。
7. 以后使用同一浏览器配置或主屏幕图标进入；无需重复安装和配对。

首页保留这条安装命令：

```sh
curl -fsSL https://pairfob.com/install.sh | sh
```

按钮旁说明：“支持 macOS 和 Linux。会自动安装所需的 Herdr 会话运行组件。”不把预先安装或学习 Herdr 列为前置条件。

### 已有 Herdr 且有任务运行

安装器识别并复用原来的可执行文件、socket、配置和工作区，不更新或重启已有 Herdr。配对后直接展示原会话。协议不兼容时解释原因并给出原安装方式对应的升级路径，不创建另一套服务绕过问题。

### 主要使用电脑浏览器

用户可以在安装 Pairfob 的同一台电脑上打开配对页，复制配对码并在终端确认。后续使用固定网址或浏览器支持的应用图标进入。访问来自本机也必须完成现有配对和会话建立流程。

不要求先配电脑再配手机。电脑浏览器与手机是可以独立选择的入口。

### 想使用电脑本地终端

安装结果和帮助入口展示：“电脑终端里运行 `herdr`，可查看同一批默认会话。”命名会话说明对应的 `herdr --session <name>`；自定义 socket 的用户显示匹配其配置的实际命令，不承诺裸 `herdr` 一定连接正确实例。

直接运行 `pairfob` 仍显示后台服务与配对状态，不改成启动会话界面。它应补充本地终端和浏览器入口提示。

### 没有安装 Agent

Pairfob 与 Herdr 可以完成安装和配对。创建页面说明所列的是支持的 Agent 类型，启动时可能需要安装或登录。保留已有纯终端入口，让用户能检查环境或执行所选 Agent 的官方安装流程。

第一版不通过 manifests 推断已安装，也不通过账户文件或额度信息推断当前启动环境一定已登录。已知“找不到命令”错误给出具体动作；无法可靠分类时展示简洁原因与诊断入口，不猜测成功。

## 四 安装行为与命令约定

### 安装状态表

| 检查结果 | 默认动作 | 完成条件 |
| --- | --- | --- |
| Herdr 缺失 | 下载、校验、记录来源、安装、启动 | 真实接口满足基础会话能力 |
| 已安装且已就绪 | 复用，不访问 Herdr 版本清单 | 原接口仍可用 |
| 已安装但未运行 | 按现有自动启动规则启动 | 接口就绪 |
| 接口不兼容 | 停止本次就绪流程，显示诊断 | 用户更新后重新检查 |
| 显式路径无效或权限错误 | 保留文件，报告具体配置 | 不覆盖错误路径 |
| 无法检查现有 socket | 停止，不另起服务猜测成功 | 明确排障后重试 |
| 用户禁用自动启动 | 尊重配置 | 用户自行启动后重新检查 |

“ready”只表示 Pairfob 所需的 Herdr 基础接口已就绪，不表示全部高级能力可用，也不表示所有 Agent 已安装或登录。浏览器继续以真实 `GetConfig.capabilities` 为功能显示依据。

### CLI 参数

| 命令或参数 | 目标语义 |
| --- | --- |
| 普通 `install.sh` | 自动补齐缺失 Herdr，继续现有登记和服务安装 |
| `pairfob setup` | 检查、自动补齐缺失 Herdr、按现有策略启动并验证；不更新已有安装 |
| `--install-herdr` | 保留兼容，等价于允许补齐依赖；不升级已有安装 |
| `--non-interactive` | 禁止提问；允许已声明的自动补齐，不授权停止运行中的任务 |
| 新增 `--no-install-herdr` | 检查和启动已有 Herdr，缺失时失败；安装脚本和 setup 均支持 |
| `--skip-herdr-check` | 仅保留在安装脚本，供离线准备；不宣称会话就绪 |
| `pairfob doctor` | 本地只读诊断，不下载、不启动、不更改配置 |
| `pairfob update` | 仅更新 Pairfob，保持已有更新行为 |
| 新增 `pairfob setup --update-herdr` | 检查来源并下载最新 Herdr；按第七节安装或暂存 |
| 新增 `pairfob setup --update-herdr --restart-herdr` | 在明确确认后为受支持的本机默认服务完成更新和重启 |

`--restart-herdr` 必须与 `--update-herdr` 一起使用；第一版与 `--non-interactive` 同用直接报参数错误。无人值守更新仅在没有运行服务且目标归属确定时激活。互相冲突的安装参数直接报错，不用参数顺序决定行为。

`--no-service`、`--no-enroll` 保留现有含义，不隐式跳过 Herdr 检查。原先非交互缺少 Herdr 会失败的行为发生变化，必须写入升级说明；需要保持原行为的脚本使用 `--no-install-herdr`。

### 安装结果与 PATH

默认输出示例：

```text
Pairfob 已安装。
会话运行组件 Herdr 已就绪。

下一步：运行 pairfob pair
在想使用的手机、平板或电脑浏览器打开 https://pairfob.com/pair

电脑终端入口：herdr
查看状态：pairfob
```

以上命令必须按实际安装结果生成。目录不在 PATH 时，主行动直接使用带正确 shell 引号的绝对路径，随后给出适合当前 shell 的 PATH 配置说明。第一版不自动修改未知 shell 的启动文件。

安装脚本通过管道运行，不能修改父 shell 的环境，也不能宣称“当前终端的 PATH 已生效”。用户路径中的空格、引号及非 ASCII 字符必须有测试。

安装失败前保留已有 Pairfob 二进制和服务的现有预检保护。出现部分完成时，显示已经完成的步骤和一条可重跑的命令；不打印无条件的“全部就绪”。

## 五 最新稳定版的获取与安装

### 官方清单

从 [Herdr 官方稳定版清单](https://herdr.dev/latest.json) 读取 `version`、`assets` 和 `sha256`。2026-10-14 核对时为 0.9.4；该版本只作为核对记录，生产代码、在线验收目标和用户文案均不得据此固定版本。单元测试使用固定清单 fixture，验证动态选择规则，不依赖当天网络结果。

每次实际需要下载时获取一次清单；本次操作固定使用该版本、平台 URL 和校验值。新版本在下载期间发布，不改变正在执行的操作。拒绝 prerelease 版本和缺少完整平台信息的清单，不自动退回固定旧版或 preview。

| Pairfob 平台 | Herdr 清单键 |
| --- | --- |
| darwin/arm64 | macos-aarch64 |
| darwin/amd64 | macos-x86_64 |
| linux/arm64 | linux-aarch64 |
| linux/amd64 | linux-x86_64 |

### 下载与发布约束

1. Go 使用结构化 JSON 解析；允许不相关的新增字段，对版本、URL、平台和校验值严格检查。清单包含历史记录，设置独立且合理的元数据大小上限，不沿用几 KB 的纯版本文本上限。
2. 元数据只从固定 HTTPS 官方源读取；下载 URL 必须匹配官方 GitHub 仓库的对应 release 和平台资产。拒绝非 HTTPS、userinfo、异常端口以及任意外部下载地址。
3. 保留现有 GitHub release 资产重定向限制。下载采用现有更新下载器可复用的超时、进度和有限重试机制；不在网络层重放会话创建等业务操作。
4. 校验 SHA-256 后再执行候选二进制的版本检查。比较候选版本与清单版本，错误时不激活。网络清单和哈希不是独立签名，不将其宣传为签名验证。
5. 临时文件放在目标文件所在文件系统。首次安装继续使用不覆盖已有文件的原子发布；并发出现文件时重新诊断，不覆盖。
6. 安装到当前用户的 `~/.local/bin/herdr`。沿用现有 Herdr 配置与默认 socket，不添加第二套专用运行环境，不要求 sudo。
7. 二进制及来源记录成功提交后启动，等待真实接口。启动失败保留可诊断的安装结果，重跑 setup 可恢复。

如果官网不可用而本机 Herdr 已兼容，正常安装和启动继续复用它，不因检查最新版本失败阻断现有工作。首次缺失且无法获取清单时停止，不降级为未校验安装。

### 并发与中断恢复

新增本机 Herdr 安装锁，锁定实际安装目标；Pairfob 安装、setup 和 Herdr 更新使用同一把依赖锁。需要同时持有服务控制锁时，统一顺序为服务控制锁、Herdr 安装锁，避免反向获取和嵌套死锁。

安装时先写入事务记录，记录目标路径、候选版本和哈希，再发布二进制，最后原子写入安装来源记录。进程在二进制发布后中断，下一次只在事务、目标所有者和哈希完全一致时补全来源记录；否则按未知来源处理。

锁只约束 Pairfob 自己的进程。提交前再次检查目标 inode、真实路径和哈希，发现外部安装器或用户修改即停止。不得声称能够完全锁住外部包管理器。

## 六 安装来源与运行状态

在实际 Pairfob 状态目录中新增 `herdr-install.json`，目录与文件沿用状态存储的用户权限策略。自定义 `PAIRFOB_STATE_DIR` 必须生效，不能硬编码默认配置路径。

最小记录字段：

| 字段 | 用途 |
| --- | --- |
| schema_version | 本地记录格式版本 |
| source | `pairfob`；无可信记录则视为 external 或 unknown |
| install_path 与 resolved_path | 安装路径与提交时的真实路径 |
| version 与 sha256 | Pairfob 最后提交的二进制身份 |
| platform 与 channel | 平台及固定 stable 渠道 |
| installed_at | 最近一次成功安装时间 |

暂存更新的版本、哈希、路径和步骤放在独立事务记录中。运行版本来自当前接口探测，不写成永久真值；最新可用版本来自本次成功获取的清单，离线时标明未知。

判断是否可由 Pairfob 更新时，同时检查记录、路径、所有者、文件类型和哈希。下列情况不能自动接管：既有安装没有记录、软链接指向包管理器、路径变化、文件被其他工具替换、显式 `HERDR_BIN` 指向另一文件。

旧版 Pairfob 曾安装过的 0.8.2 如果没有来源记录，也不能只靠路径或已知哈希推定归属。第一版显示明确的外部安装维护说明，不做静默迁移或覆盖。

诊断区分这些事实：未安装、已安装但停止、接口就绪、接口不兼容、无法检查、更新已暂存、已安装版本与运行版本不同。状态细节首先放在 CLI；第一版不扩展 RPC 把来源记录发送到浏览器。

## 七 本机 Herdr 更新与生效

### 更新责任

| 安装来源 | Pairfob 的责任 |
| --- | --- |
| Pairfob 安装且记录仍匹配 | 下载、校验、暂存或激活、就绪验证、具体诊断 |
| Homebrew、mise、Nix 等 | 复用并提示通过原管理方式更新，不代替其管理器写文件 |
| Herdr 官方安装器 | 引导使用其官方更新入口，解释可能的重启影响 |
| 来源不明或已被外部替换 | 明确显示无法确认来源，提供本机检查步骤，不猜测包管理器 |

[Herdr 官方安装文档](https://herdr.dev/docs/install/#update)说明官方直接安装可使用 `herdr update`，包管理器安装使用原管理器。其兼容服务器可继续运行，老版本服务器可能需要停止；实验性 `--handoff` 不作为本方案默认路径。Pairfob 自己直接下载的安装走本方案下载器，不未经验证地假设等同于官方安装器管理的安装。

### 第一版采用明确的维护时机

第一版不在已有服务运行时替换 Herdr 二进制。这样避免未验证的新客户端与旧服务组合影响 Pairfob 的本地 terminal bridge。更新入口可以先下载并校验，用户再选择重启时机；不要求发现新版本就立刻停任务。

`pairfob setup --update-herdr` 的流程：

1. 检查归属和当前 CLI 版本。没有可信归属则显示对应维护方式，不下载到原文件上。
2. 获取官方最新稳定版；若当前文件哈希一致，报告文件已最新，同时独立检查运行版本。运行版本仍旧时不报告全部完成；带重启参数的请求继续执行服务生效流程。
3. 下载、校验并暂存候选。拒绝自动降级：当前文件高于稳定版或无法比较时保留现状。
4. 枚举实际配置下的默认与命名服务。无法完整检查时不激活。
5. 没有运行服务且没有独立外部 supervisor 时，暂停会竞争启动的 Pairfob 用户服务，获取控制锁，复查后激活并启动默认 Herdr；最后恢复 Pairfob 原来的运行状态。
6. 存在运行服务时保留旧文件和任务，输出“更新已准备，当前仍运行旧版”，以及下一条命令。新候选不得被描述成已安装。

需要立即生效时运行：

```sh
pairfob setup --update-herdr --restart-herdr
```

该命令在 `/dev/tty` 上先显示当前版本、目标版本、目标电脑、默认服务及将受影响的会话，再询问是否停止并重启，默认答案为否。确认文本明确“会终止此服务中的终端进程，Agent 可能需要恢复”。不以 idle 状态代替用户决定。

第一版只自动重启能确认属于当前用户、使用匹配配置且由本流程管理的默认服务。若存在运行中的命名会话、自定义 socket、外部 supervisor 或无法识别的服务，保留暂存更新，列出阻止生效的具体对象，由用户在本机维护后再运行更新命令。不得停止一台电脑上的所有 Herdr 实例来求成功。

确认后的顺序是：记录原服务状态、暂停 Pairfob 的竞争启动、重新核对 Herdr 目标、停止指定默认服务、等待退出、原子替换并提交来源记录、启动 Herdr、检查版本与基础接口、恢复 Pairfob、验证连接。影响范围在确认前后变化时中止并重新展示，不沿用过期确认。

进程身份或运行状态无法核实时停止。独立前台 Pairfob 或外部服务无法安全协调时，显示具体停止步骤，不强行杀进程。启动协调使用本机锁与状态，不改变远程协议。所有退出路径都尝试恢复被本次操作暂停的 Pairfob 原状态；恢复失败独立报告，不把用户原本停止的服务意外开启。

### 更新结果与恢复

| 结果 | 输出与恢复 |
| --- | --- |
| 文件和服务都已最新 | 成功，并打印实际运行版本 |
| 候选已暂存，运行服务未改变 | 明确 pending；建议 CLI 退出码 2，脚本可识别尚未生效 |
| 下载或校验失败 | 退出码 1，旧文件及服务保持原状 |
| 用户拒绝重启 | 保留暂存，退出码 2 |
| 新版未能启动或接口不兼容 | 保留日志，尝试恢复旧二进制和原服务运行状态，报告实际恢复结果 |
| 恢复旧版也失败 | 退出码 1，打印恢复文件、日志位置和手动步骤；不声称已回滚成功 |

保留一个旧二进制备份直至新服务就绪。二进制回退不能保证撤销上游配置迁移或恢复被停止的 PTY 进程；更新前确认及失败输出都要说明这一点。不要循环自动停止、启动或反复尝试不同版本。

暂存更新可在后续命令中复用，但新的显式更新请求先读取最新清单；清单版本变化时重新下载候选。断网不能把旧暂存版本称为“官方最新”。事务中断后先核对实际文件与服务，再决定恢复；不重放已经完成的停止或替换步骤。

### 用户在哪里找到更新

`pairfob --help`、`pairfob setup --help`、本地状态说明、安装文档和 CLI 文档列出 Herdr 更新命令。PWA 设置现有更新入口明确标注“更新 Pairfob”；另提供“会话运行组件的更新方法”帮助入口，指导在目标电脑执行命令。

第一版不在 PWA 宣称已检查 Herdr 最新版，也不增加一个实际更新不了 Herdr 的按钮。将来要远程管理时，另行设计能力声明、状态机和用户确认。

## 八 创建首个会话与 PC 使用引导

### 空会话页面

沿用现有空状态和创建表单，不增加独立强制 onboarding 向导。主按钮是“创建第一个会话”，与其他会话创建入口调用同一逻辑。

表单明确显示目标电脑名称。全新用户没有最近目录时，直接解释“输入这台电脑上的项目绝对路径”；电脑用户可以在项目目录的终端运行 `pwd` 并复制结果。手机用户也清楚该路径属于电脑，不是手机。

保留最近目录和已有工作区快捷选择。第一版不新增目录浏览 RPC，不把整个文件系统加入允许范围。路径必须在现有允许范围内，且是已存在的目录；不能确认时拒绝创建并保留用户已填内容。错误沿用现有协议错误码，不新增目录探测 RPC。

触屏打开表单不无故弹键盘；用户明确选择输入路径后可以聚焦。鼠标、键盘与触屏行为沿用现有 input mode 辅助函数，不以窗口宽度推断交互方式。

### Agent 选择与失败

选项来源继续遵守服务端广告的类型与 capabilities；标签使用“Agent 类型”，不使用“已安装”。未做安装探测时，不默认声称某个选项可以立即运行。

成功创建资源不等于 Agent 已登录。启动失败时沿用当前补偿和 receipt 语义：如果临时工作区已清理，保留表单让用户修复后主动重试；如果结果未知，只刷新确认，不自动再创建一遍。纯终端退路必须由用户主动选择，不能在失败后偷偷改成另一个成功操作。

“需要登录”有可靠证据时给出进入终端的动作，否则展示 Agent 的实际输出。真实 Herdr 可能先确认启动命令已发送，再由 shell 输出 `command not found`；此时保留真实终端供用户查看，不把它描述成 Agent 已安装或已登录。Pairfob 不收集密码、不代替用户登录、不把 Agent 凭据写入服务环境。

### 本地状态与帮助文案

本地 `pairfob` 状态页补充三个入口：继续配对、电脑终端、完整诊断。更新及故障信息按需出现，不把所有命令挤进正常状态输出。

首次使用说明包含以下区别：

| 用户动作 | 实际结果 |
| --- | --- |
| 关闭 Pairfob 网页或应用窗口 | 断开此客户端，电脑上的任务继续 |
| 关闭本地客户端窗口 | 与主动停止会话区分；按实际 Herdr 行为验收和说明 |
| 停止 Pairfob 服务 | 远程连接断开，不主动停止 Herdr 或 Agent |
| 在会话里退出 Agent 或停止 Herdr 服务 | 对应任务或终端进程会结束 |
| 锁屏 | 在系统继续运行和联网的前提下可连接 |
| 睡眠、注销、重启 | 不能保证任务继续；恢复连接与恢复 Agent 进程分别处理 |

登录服务只能承诺登录后启动，不能写成未登录时也一直运行。重启后是否恢复历史 Agent 由 Herdr 和 Agent 的恢复能力决定；本方案必须验收重新登录后可以创建新会话，不承诺所有旧进程原样存活。

## 九 启动环境与卸载

### PATH 与诊断

继续保存已检查的 Herdr 绝对路径及当前允许保存的运行配置。Agent 环境同时覆盖安装终端启动和登录服务启动，测试包括常规安装路径以及 nvm、mise 或 asdf 等代表性路径。

优先通过 Herdr 支持的 shell 初始化与配置解决 Agent 启动环境。确需传递可执行目录时，仅处理明确的绝对目录及必要配置，给出诊断；不复制整份 shell 环境，不持久化 token、API key 或临时代理凭据。重登后找不到 Agent 时提示实际缺失的程序和可恢复动作。

保留 Herdr 启动失败的有界日志或日志位置，注意脱敏和权限。`doctor` 分别报告 Pairfob、Herdr 文件、Herdr 服务、socket 和运行版本；失败时给一条优先执行的恢复命令。

### 卸载与归属结束

沿用现有 Pairfob 服务及二进制卸载路径。输出明确保留 Herdr、会话、项目和现有状态数据。配对凭据删除是独立动作，需要用户知道设备将失效。

第一版不提供自动移除 Herdr 按钮。用户删除 Pairfob 状态目录后，来源记录随之丢失；再次安装时按未知来源处理，不能凭路径重新取得管理权。

### 大文件超时进一步排查

同机单独执行 `TestWorkspaceMediaEncryptedRPCBoundarySizes/32MiB-download`：修改前普通模式约 26 秒、竞态模式约 56 秒均通过。该测试通过进程内 `mux.Pipe` 传输；正常模式还保留每会话网络计费 2 MiB/s 的限速，因此 32 MiB 经 Base64 编码后的传输存在约 21 秒的限速下限。普通模式 CPU 采样约 3.72 秒；竞态模式约 48.16 秒，主要额外成本是 race/TSan 插桩和重复 JSON 扫描。此前超时为测试包累计达到默认 10 分钟，并无证据表明单个下载请求死锁。

修正了两处实际问题：

1. `internal/phone` 的进程内测试客户端先完整反序列化一次响应以取得路由字段，再完整反序列化一次取得结果；改为一次解析同时取得这些字段。增加带加密帧的大载荷响应、错误响应、终端事件、事件与请求 ID 区分及非法 JSON 回归测试。没有修改线上的浏览器协议、加密字节或媒体 RPC 字段。
2. `runtimeRPCClient` 测试 fixture 之前只关闭停止信号，阻塞在 `Pipe.Recv` 的协程及会话工作协程仍可能存活；清理时现在关闭上传系统、重置会话并关闭双方通道。新增测试验证会话停止信号、会话表和通道确实关闭。

修正后 macOS `go test -race ./internal/daemon -count=1` 的 223 个顶层测试（含子测试共 269 个通过事件）全部通过，整包约 300 秒；其中 32 MiB 用例约 48 秒，文件边界组约 67 秒。仍使用原定 600 秒整包上限，未缩小数据量、改变限速或放宽断言。运行负载也会影响耗时，不能把前后所有时间差全部归因于同一处代码修改。

### 真实服务故障补测

在同一隔离服务测试中追加两类故障，macOS `TestRealServiceRecovery` 实际运行约 49 秒通过，CLI 包 `go vet` 通过：

- 下载通道不可用：只为 CLI 子进程配置返回 503 的本地代理，确认请求确实到达代理。显式 Herdr 更新退出码为 1，并报告读取最新版本失败；已安装二进制与来源记录逐字节不变，原 Herdr 进程保持可用，仍可创建和关闭真实终端。
- 离线启动：停止隔离 Herdr 后，在同一下载故障配置下运行普通 `setup`，退出码为 0，代理没有收到新请求，真实终端创建和关闭成功。该结果验证已安装组件启动不依赖下载服务，不表示首次安装可以离线完成。
- Pairfob 进程崩溃：核对独立测试服务的 admin 身份与候选可执行文件后发送 SIGKILL；不执行 start/restart 命令，等待 launchd 自行启动。新 PID、实例标识和服务管理器记录一致；Herdr 进程身份保持不变，之后仍可创建真实终端。接续的正常停止、冷启动、重启和卸载保留 Herdr 验证也通过。

本轮使用先前从官方获取并经过清单、SHA-256 和版本校验的 Herdr 0.9.4 缓存，专门隔离下载故障，不重复声称完成了新的在线下载验收。测试使用临时 HOME、独立服务名和 socket，结束后删除测试服务与运行组件。仅新增、扩展测试及本节记录，产品实现未变，因此复用上一轮 Docker 全仓结果，没有重跑无关 PWA/Worker 测试。此补测尚不代表 Linux systemd 实机故障恢复或已运行 Agent 任务的状态恢复。
